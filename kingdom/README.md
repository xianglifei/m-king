# 麦门制霸图（m-king v2）

> **全城制霸，吃遍麦门。**
> 把你所在城市的每一家麦当劳画成一张 Q 版游戏地图：旗舰店是王都，商场店是城镇，
> 得来速与社区店是街角甜品站。每**真实吃过**一家没吃过的店（打卡 / 订单导入），
> 它的整片领地就从云朵迷雾里点亮——直到全城插满你的旗。

**设计原则：点亮只由真实用餐记录驱动。**这里没有"一键随机点亮"——
制霸的意义就是"我真的去过"，地图是吃饭的记账本，不是点击游戏。

![玩法示意](../references/kingdom-preview.png)

## 它解决什么

「吃过哪些麦当劳」本来只是一串订单记录。这张图把它变成三件事：

1. **一个看得见的进度**——版图占比按领地**面积**计算（Voronoi 划分），不是门店数：
   吃在门店密集的城区推进很慢，远征一次密云延庆却一步开疆一大片。
2. **一个可积累的身份**——战功（城邦等级 × 远郊加成 + 开疆奖）与称号阶梯：
   麦门路人 → 见习麦民 → 麦田巡逻官 → 金拱门骑士 → 堡垒男爵 → 边疆侯爵
   → 巨无霸公爵 → 麦门亲王 → **制霸者·麦门之主**。
3. **一个会回去的理由**——编年史记着每一城的点亮日期；下次想下单一抬头，
   地图上有大片迷雾在等你。

## 用餐打卡（核心交互）

- 点右上「用餐打卡」→ 搜索/浏览未点亮城邦 → 选今天吃的那家 → 领土点亮 + 彩带战报；
- 或在地图上直接点未点亮城邦 / 悬停后按卡片上的「我吃了这家 · 打卡」；
- 手滑点错了？编年史旁「↩ 撤销上次打卡」随时回退；
- 真实模式下同一入口补录历史（订单接口只回最近 ~10 单的缺口就靠它）。

## 快速开始

```bash
# 方式一：直接玩（内置北京演示数据，虚构门店，无需任何凭据）
open kingdom/index.html          # 或双击，file:// 可用

# 方式二：起本地服务（支持滚轮缩放/拖拽平移）
python3 -m http.server 8799 --directory kingdom
# 浏览器打开 http://127.0.0.1:8799/

# 方式三：接入你的真实数据（需要麦当劳 MCP Token）
export MCD_MCP_TOKEN=你的Token    # 与 WorkBuddy mcp.json 中 mcd-mcp 相同
python3 kingdom/tools/fetch_mcd_data.py
python3 -m http.server 8799 --directory kingdom   # 刷新即见你的真实王国
```

## 真实数据怎么来

`tools/fetch_mcd_data.py`（零依赖，纯标准库）：

| 步骤 | 做法 |
|---|---|
| 门店清单 | 优先网格扫描：对城市范围按 ~6km 网格逐一调用 `query-nearby-stores`（若接口支持坐标入参）；否则退化为城市×关键词搜索 |
| 门店坐标 | 麦当劳 MCP 不返回门店经纬度（社区已知结论）。若返回体带 distance 字段，用 ≥3 个不同原点的距离做**三边定位最小二乘**反推坐标（`accuracy: trilaterated`）；否则取首次出现的网格单元（`grid-cell`） |
| 征服记录 | `order-list` 订单按门店聚合，与扫描结果按 storeCode/名称匹配；订单门店不在清单时单独建点 |
| 累积档案 | `data/visits.json` 合并写入、不覆盖——历史订单接口只返回最近约 10 单，档案请长期留存 |

⚠ 门店坐标为估算值（精度见 `accuracy` 字段），服务游戏化呈现，不承诺门牌级精确。
⚠ 遵守麦当劳 MCP 服务规则：脚本内置调用间隔（默认 0.8s），请勿调小、勿并发。

## 隐私红线（务必读）

- **真实门店名 ≈ 位置信息**：常去门店等于住址/公司附近，是强定位信号。
- 公开分享、截图、部署演示页之前，必须生成脱敏版：
  ```bash
  python3 kingdom/tools/fetch_mcd_data.py --sanitize
  ```
  门店名替换为「示例门店A/B/C…」，区县归并为「示例郡」，storeCode 置空。
- `data/` 目录请加入 `.gitignore`，不要把真实数据提交到公开仓库。

## 产品机制速览

- **点亮唯一入口是用餐打卡**：右上按钮搜索选店 / 地图点选二次确认 / 悬停卡「我吃了这家」；支持「↩ 撤销上次打卡」。
- **手动打卡本地持久化**（localStorage，演示/真实模式分开存档），刷新不丢；订单接口只有最近 ~10 单，更早的靠打卡与 visits.json 积累。
- **下一目标卡**：优先提示"只差一家就全郡点亮"的城邦，否则推荐当前战功最高的远征目标。
- **成就徽章墙**（8 枚）：初来麦到 / 小有所成 / 攻城拔寨 / 半壁江山 / 王都克星 / 开疆拓土 / 远征军 / 制霸在望。
- **称号晋升时刻**：跨过称号阈值时战报横幅升级为"晋升"形态并加撒彩带。
- **战绩分享卡**：一键生成 900×1280 战绩 PNG（版图快照 + 四项数据 + 称号 + 徽章），用于社交传播。
- **触屏支持**：Pointer Events 统一鼠标/触摸，单指拖拽、双指捏合缩放。
- 首次访问自动弹出玩法说明；Esc 可关闭任何弹层；「重置演示」需二次确认。

## 与旧版（六门技能）的关系

v1 的六个技能（麦价指数/年度账单/积分理财/三路比价/券管家/热量教练）仍在 `main` 分支。
v2 把「年度账单」的回顾欲放大成一张可征服的地图，作为新的产品主体；
省钱算价等能力后续作为地基模块回归（点单默认最优价），不再作为独立亮点。

## 已知边界

- 演示门店为虚构门店 + 真实地标坐标（±1~2km），空间关系与真实北京一致；
  二三四五环为近似装饰环线（±1km）。真实门店清单与坐标以 MCP 扫描为准。
- 门店坐标估算精度取决于接口是否返回 distance 字段，可能有数百米至数公里偏差。
- 历史订单只有最近 ~10 单，更早的征服需要你在 visits.json 中手工补录（格式：`{"storeId","date"}`）。
