## 它长什么样

页面中间是一座中式宫门造型的麦当劳大房子（朱红墙体 + 金黄琉璃顶 + 发光的金拱正门），左右各守三门技能。顶部和门内是**你账户的实时数据**：可用积分、券包数量、已过期积分、当日活动日历。

点任意一门：

1. 金拱两扇门**向两侧推开**（"推门进殿"动效）
2. 页面实时显示**正在调用哪个 Tool**
3. 门开之后，是一份**排好版的结果**——关键数字、对比表格、条形榜、结论说明
4. 结果面板顶部列出**这次真实走过的每一步调用链和耗时**

```
点击 → 本地服务直连麦当劳 MCP → 计算 → 结果渲染回页面
```

全程不复制、不跳转、不粘贴。

## 六个技能

| 门 | 技能 | 它到底算什么 | 用到的 MCP Tool |
|:--:|---|---|---|
| 左一 | **中国麦价指数 McIndex** | 拉真实门店菜单，试算「主食+小食+饮品」三件套的**当期麦价读数**，并排出折扣力度榜 | `now-time-info` `query-nearby-stores` `query-meals` |
| 左二 | **麦当劳年度账单** | 用历史订单 + 官方营养表，算出这一年**吃了多少顿、花了多少钱、摄入多少热量**，并折算成"跑了多少公里" | `order-list` `list-nutrition-foods` |
| 左三 | **积分理财师** | 把积分商城兑换券按**「每一分能换多少钱」**排序，告诉你积分该怎么花最值，并预警过期 | `query-my-account` `mall-points-products` `query-lottery-info` |
| 右一 | **三路比价器** | 同一份餐，按**到店自取 / 得来速 / 麦乐送**逐路真实算价（含配送费与打包费），告诉你走哪条路最省、差多少 | `query-nearby-stores` `delivery-query-addresses` `delivery-query-stores` `query-meals` `calculate-price` |
| 右二 | **券生命周期管家** | 把每张券和菜单价对上，算出**「这张券值多少钱」**，再按到期紧急度排出使用顺序 | `available-coupons` `query-my-coupons` `query-meals` |
| 右三 | **热量预算教练** | 给定热量预算和价格上限，**穷举本店在售餐品的全部可行组合**，给出三套方案并折算跑步公里数 | `list-nutrition-foods` `query-nearby-stores` `query-meals` |

> 为什么不做成一个按钮干所有事？因为 Skill 是"给 AI 的说明书"，一个大而全的描述会让触发变糊、深度被摊薄。**入口统一、模式独立、结果可视化**——这是 m-king 的结构选择。

## 快速开始

### 前置条件

- **Node.js 18+**（用到内置 `fetch`，无第三方依赖）
- 一个**麦当劳 MCP Token**（免费申请，见下）
- 可选：腾讯 WorkBuddy（用于把 m-king 当作 Skill 调起）

### 第 0 步 · 拿到代码

```bash
git clone https://github.com/xianglifei/m-king.git
cd m-king
```

### 第 1 步 · 申请麦当劳 MCP Token

1. 打开 <https://open.mcd.cn/mcp>
2. 手机号验证登录
3. 右上角「控制台」→「激活」→ 复制你的 Token

### 第 2 步 · 让 m-king 拿到 Token（三选一）

**方式 A（推荐）**：你已经用 WorkBuddy 配好了麦当劳连接器，那么**什么都不用做**——m-king 会自动读取 `~/.workbuddy/mcp.json`。

**方式 B**：项目内本地配置（已被 `.gitignore` 忽略，不会误提交）

```bash
cp mcp-config.example.json mcp.config.json
# 编辑 mcp.config.json，把 ${MCD_MCP_TOKEN} 换成你的真实 Token
```

**方式 C**：环境变量

```bash
export MCD_MCP_TOKEN="你的Token"
```

### 第 3 步 · 起服务

```bash
cd m-king
node server.js        # 或 npm start
```

```
  🍟  m-king · 麦门总管
  ────────────────────────────────────────
  服务地址   http://127.0.0.1:8799/
  MCP 端点   https://mcp.mcd.cn
  Token      已就绪（来源：~/.workbuddy/mcp.json）
  已加载模式 6 个
```

### 第 4 步 · 打开浏览器

访问 <http://127.0.0.1:8799/>，点任意一门。页面顶部的门店选择器可以切换基准门店（麦价指数 / 券管家 / 热量教练会用到）。

> 服务只监听 `127.0.0.1`，不对局域网或公网开放，并校验请求的 Host 头（防 DNS rebinding）。端口被占用时会自动顺延（8799 → 8800 → …）。
> 可用 `MCD_PORT=9000 node server.js` 指定端口，`MCD_CITY=上海` 指定默认搜索城市；`MCD_CACHE_TTL_MS=0` 可关闭门店/菜单的短缓存（默认 45 秒，命中会在调用链里标注 `(cache)`）。

### 其他命令

```bash
npm test        # 单元测试 + server 安全基线测试（node:test，零依赖）
npm run demo    # 重新生成脱敏静态演示页 demo/index.html（需先起服务）
```

### 例 1 · 三路比价：同一份餐，走哪条路最省？

点「三路比价器」，返回：

```
77.50 元 实付
到店自取 · 比最贵那条省 ¥16.00（17.1%）
基准篮子：双层猪柳蛋麦满分×1 + 牛奶×1 + 麦咖啡热美式中杯×1 + 巧克力味厚松饼猪柳蛋堡×1

履约方式      门店                    商品小计   配送费   打包费   实付     判定
到店自取      北京·示例门店A          ¥77.50     —        —      ¥77.50   🏆 最省
得来速车道    北京·示例门店C          —          —        —      —        不可用：门店暂停营业
麦乐送        北京·示例门店B          ¥84.50    ¥6.00    ¥3.00    ¥93.50   + ¥16.00
```

> 示例输出中的门店名已脱敏（演示页同样处理，见 `lib/sanitize.js`）。

页面底部会说明口径：**同款商品在到店菜单和外送菜单上的标价本身就可能不同**，这正是差价的主要来源——通常没人注意到这点。

### 例 2 · 券值多少钱？

点「券生命周期管家」，它会拉你的券包 + 门店菜单，把券商「用券价」和菜单标价对上：

```
火腿扒堡早餐两件套  →  对应餐品 芝芝火腿扒堡  →  菜单价 ¥13.00  →  用券价 ¥9.90  →  省 ¥3.10
```

匹配不上的券（限定品、跨门店券）会**明确标为「未匹配」，不做臆测**。

### 例 3 · 我的积分该换什么？

点「积分理财师」，它按「每一分积分能换到多少现金价值」排序：

```

18.8元板烧鸡腿堡两件套（100分）     ¥0.1880/分
6.9元可乐麦炫酷（50分）             ¥0.1380/分
...
止损结论：你有 1360.7 分已经作废 —— 相当于丢掉了约 ¥511.62（按当前最优兑换率折算）。
```

```
└── workbuddy.md              # WorkBuddy 对话上下文
```

**为什么需要本地服务？**
纯静态网页的 JavaScript **够不到 MCP**（MCP 是服务端能力），所以"点按钮→网页自己干活"必然点不动。m-king 的做法是在本地起一个只监听回环地址的小服务，把"网页的点击"翻译成"真实的 MCP 调用"——**这才叫能执行**。

**接口一览**

| 方法 | 路径 | 作用 |
|---|---|---|
| GET | `/api/status` | Token 是否就绪、端点、已加载模式、工具清单 |
| GET | `/api/dashboard` | 首页看板：积分、券、门店、当日活动（真实数据） |
| POST | `/api/run` | 执行一个模式：`{"mode":"fulfillment-compare","options":{}}` |
| POST | `/api/tool` | 单次裸调用（调试用，带工具名白名单） |

## 设计取舍（诚实说明）

这份项目里有几个地方我们**故意没有把话说满**：

- **麦价篮子会标注替代项**。早餐时段没有薯条，篮子里的"小食"位置就会标注"本时段无在售"，**不会拿别的商品硬凑**。
- **券的匹配可能失败**。券名和菜单名对不上时，结果里会写「未匹配到同款」，而不是编一个差价出来。
- **热量是估算**。营养匹配走的是名称模糊匹配，组合是穷举而非推荐算法拟合，跑步换算按 60 kcal/公里粗估。
- **抽奖不给期望值**。概率不公开，静态算不出可信的期望值，所以只给"能抽几次"。
- **链接时效**。价格、券、活动都会变，页面显示的都是**取数那一刻**的真实快照，不在前端做任何缓存美化。

## 常见问题

**Q：为什么不用纯前端？**
A：MCP 是服务端能力，浏览器 JS 无法直接调用。要做"点了就执行"，必须有本地服务做桥。

**Q：Token 会不会泄露？**
A：不会。Token 只在本地 [`lib/mcp.js`](lib/mcp.js) 进程内使用，**不写入任何日志、不包含在任何 API 返回体里、不出现在页面源码中**。仓库里只有 `mcp-config.example.json` 这个纯占位符示例。

**Q：会不会误下单？**
A：不会。m-king 只调用**查询类**和**算价类** Tool（`query-*` / `calculate-price` / `list-*` / `mall-points-products` 等），**不调用任何写入类能力**（`create-order` / `auto-bind-coupons` / `draw-lottery` / `party-order-create` 一律不碰）。调试端点 `/api/tool` 使用**精确工具名白名单**（仅含上述只读工具），前缀撞名的写入类工具同样会被拒绝。涉及"领取/下单"的动作只会在文字结论里**建议**你去做。

**Q：演示快照里是谁的数据？**
A：是开发者本人的一次真实调用结果，但生成时经过 `lib/sanitize.js` 脱敏：门店名称替换为「北京·示例门店A/B/C…」（常去门店≈常驻位置，是最强的定位信号），订单时间打码到月份（保留消费故事的形状，抹掉行为时间线）。金额与积分保留，因为它们是演示的故事线且不构成定位。

**Q：能改成我自己的门店/城市吗？**
A：可以。`MCD_CITY=上海 node server.js`，或写进 `mcp.config.json`。门店优先用你的收藏门店。
